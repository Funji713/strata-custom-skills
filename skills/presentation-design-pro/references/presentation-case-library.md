# Actual Presentation Case Library

These are real public presentations, recordings, or presentation PDFs. They are calibration material, not templates to reproduce. Before using a case, view the full PDF or at least five consecutive minutes of a recording, identify its audience and intended decision, and record the two or three elements worth adapting.

## Selection Guide

| If the requested deck is ... | Start with this case | Then add |
| --- | --- | --- |
| Product announcement | Apple Events or Figma Config | One relevant product or customer proof source |
| Technical conference keynote | Google I/O or Figma Config | One live demo, architecture, or benchmark evidence source |
| Startup pitch | Buffer | Current market and traction evidence supplied by the user |
| Investor or board update | NVIDIA investor or annual meeting presentation | Required finance, legal, and governance sources |
| Research or thesis defense | Penn State model talks | Original paper, methods, results, limitations, and citations |
| Data-heavy narrative | Hans Rosling | FT Visual Vocabulary and the underlying dataset |
| Policy, nonprofit, or advocacy deck | World Bank or Drawdown | Primary policy, program, or impact evidence |
| Training or rollout deck | NASA implementation deck | Audience-specific instructions, owners, dates, and success criteria |

## Adaptation Protocol

1. Match the case to audience and delivery context before matching the aesthetic.
2. Write down the observed pattern: for example, "one claim followed by a large product demo" or "headline KPI followed by small-print disclosure."
3. Rebuild the pattern with the user's own story, data, brand system, and imagery.
4. Cite the user's facts independently. A case is never evidence for the new deck's claims.
5. If no case matches, use the theory guide and create a new visual system rather than forcing a borrowed style.
